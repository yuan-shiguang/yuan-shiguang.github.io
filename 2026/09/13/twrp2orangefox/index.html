从 TWRP (A9.0) 设备树迁移到 OrangeFox (A12.1) 设备树

以小米 Mi 8 SE（sirius）为例。两棵树：

  • 旧树：android_device_xiaomi_xmsirius —— TWRP/Omni 时代的 A9.0 树，代号 xmsirius
  • 新树：android_device_xiaomi_sirius —— OrangeFox 官方 A12.1 树，代号 sirius

设备完全相同（SDM710 / Mi 8 SE），差异全部来自 Android 版本演进（A9 → A12） 和 Recovery 框架演进（旧 TWRP → OrangeFox）。下面按文件逐个讲解怎么改。

一、总览：目录结构对比

核心变化一句话：A10 起 recovery ramdisk 改用 system-as-root 风格布局，HAL 服务从 /sbin 手动管理变成 /system/bin + /vendor + VINTF manifest 自动注册。

7. OrangeFox 专属 flag

其余 TWRP flag（主题、加密、NTFS、CPU 温度路径等）两棵树基本一致，直接保留即可。

四、recovery/root 布局改造（重点）

这是 A9 → A12 工作量最大的部分。

1. sbin 目录拆分

旧树把服务二进制和依赖库全塞在 sbin/，新树按分区语义拆开：

旧树位置 新树位置 内容
sbin/qseecomd 等服务 system/bin/ qseecomd、gatekeeper@1.0-service-qti、keymaster@4.0-service-qti
sbin/*.so system/bin/ 同级 服务自身依赖（与二进制同目录）
vendor/lib64/*.so vendor/lib64/ qsee 依赖库（libQSEEComAPI、librpmb、libdrmfs 等）
— system/etc/twrp.flags 新增，TWRP 分区 flag

keymaster 从 3.0 升级到 4.0：system/bin/ 里换用 android.hardware.keymaster@4.0-service-qti，依赖库增加 libqtikeymaster4.so。这批二进制不是凭空来的——从你想支持的 A11/A12 ROM 的 vendor.img 里提取，版本必须与目标 ROM 匹配，否则解密必挂。

2. VINTF manifest 重组

  • 删除 vendor/compatibility_matrix.xml（A9 ramdisk 方案，已废弃）
  • 删除 vendor/manifest.xml（旧位置）
  • 新增 system/etc/vintf/manifest.xml —— framework 侧 manifest（system-sdk 声明 28–31）
  • 新增 vendor/etc/vintf/manifest.xml —— device 侧 manifest（target-level="3"，sepolicy 31.0，keymaster 声明为 @4.0）

新的 device manifest 同样从目标 ROM 的 vendor/etc/vintf/manifest.xml 提取后精简（只保留 recovery 解密需要的 gatekeeper/keymaster/qseecom 相关及基本 HAL）。

3. ueventd

删除 root/ueventd.qcom.rc，新增 root/vendor/ueventd.rc（从 A12 ROM vendor 提取），并保留关键的固件路径声明：

以及 /dev/qseecom 0660 system drmrpc 等解密所需节点权限。

4. 删除 fstab.qcom

旧树 ramdisk 里带一份 fstab.qcom（含 fileencryption=ice）。A12 方案下 recovery 只认 BOARD_RECOVERY_FSTAB 指定的 recovery.fstab，ramdisk fstab 删掉。

五、init.recovery.qcom.rc 重写

旧树（A9 风格）核心是手动管理解密服务：手写一堆 service 定义，再用 crypto.ready 属性开关启停 qseecomd / keymaster-3-0 / gatekeeper / hwservicemanager / servicemanager，还带一段 CPU 调频脚本。这些全部删掉。

新树全文只有 24 行：

要点：

  1. import /init.recovery.qcom_decrypt.rc —— OrangeFox 公共树（device/xiaomi/sdm845-common）提供的解密脚本，keymaster/gatekeeper/hwservicemanager 的服务定义和启动时序全在里面，由 VINTF manifest 自动注册，设备树不用再管。
  2. export ANDROID_ROOT /system_root —— A10+ 的 recovery 用 system-as-root，system 挂载点变了。
  3. symlink /sbin/busybox /system/bin/sh —— system/bin 里的服务脚本需要 sh。
  4. 旧树里的 CPU governor / perf-mode 调优已上移到公共树，设备树不再保留。

六、init.recovery.usb.rc 改写

主要差异是 USB VID/PID 与 gadget 配置：

旧树 (xmsirius) 新树 (sirius)
idVendor 0x2717（小米） 0x18d1（Google）
adb PID 0xFF08 0x4ee7
mtp,adb PID 0xFF48 0x2d08
mass_storage 有 无
vendor 属性 setprop vendor.usb.controller、enable vendor.qcom-usb-sh 无

迁移时建议直接采用新树版本：Google 官方 VID/PID 在各类系统上驱动兼容性最好；vendor.qcom-usb-sh 是 A10+ 的 init 扩展，A12 ramdisk 里依赖环境不同，容易踩坑。

七、recovery.fstab：FDE → FBE

这是解密方案的代际差异，diff 如下：

解读：

  1. encryptable=footer（FDE 全盘加密）→ fileencryption=...（FBE 文件级加密）：A10 起 MIUI/类原生全部转向 FBE，v1 policy 指定加密算法，OrangeFox 的 qcom_decrypt.rc 靠这个 flag 识别加密类型。
  2. 新增 /metadata：FBE 存放密钥元数据，Mi 8 SE 没有独立 metadata 分区，借用 cust 分区（这也是 MIUI 官方做法）。
  3. 新增 /dtbo：A10+ ROM 普遍需要独立刷 dtbo，备份列表里必须有它。
  4. /data 文件系统 ext4 → f2fs：跟随新版 ROM 的实际格式。
  5. USB OTG 节点从 sda1 改为 sdg1（UFS 机型盘符顺序在新内核下有变化，按你实际内核实测调整）。

八、OrangeFox 专属配置

  1. 继承公共树：本设备树继承 device/xiaomi/sdm845-common（qcom_decrypt.rc、性能脚本、通用 vendor 库都在那），该仓库由 OrangeFox 源码的 vendorsetup.sh 自动克隆，无需手写依赖。
  2. 构建变体（README 中说明）：
    • 默认：标准构建
    • export FOX_USE_DYNAMIC_PARTITIONS=1：给刷了 retrofit 动态分区 ROM 的用户
    • export FOX_USE_KEYMASTER_4=1：给借用 keymaster 4.0 的 ROM
  3. OF_USE_LEGACY_BATTERY_SERVICES := 1：老内核电量读取（见第三节）。

九、编译

产物在 out/target/product/sirius/recovery.img，fastboot 刷入即可。

十、常见坑汇总

坑 原因 解法
编译报 duplicate rules / ELF prebuilt 错误 A12 构建检查严格 BUILD_BROKEN_DUP_RULES + BUILD_BROKEN_ELF_PREBUILT_PRODUCT_COPY_FILES
进 recovery 黑屏/花屏 像素格式变了 保持 TARGET_RECOVERY_PIXEL_FORMAT := "BGRA_8888"
解密失败 / data 无法挂载 keymaster 版本或 manifest 与 ROM 不匹配 从目标 ROM vendor.img 提取配套服务与 manifest
电量显示 0% 或不刷新 A12 框架读不到老内核电池节点 OF_USE_LEGACY_BATTERY_SERVICES := 1
adb 识别不到设备 usb.rc VID/PID 或 UDC 属性问题 用新树 usb.rc；确认 sys.usb.controller=a600000.dwc3
亮度调节异常 TW_MAX_BRIGHTNESS 重复定义被覆盖 只保留一处定义
刷完 ROM 无法开机 漏了 dtbo / persist 备份恢复 fstab 补全 /dtbo、/persist 条目

结语

整个迁移的本质是三件事：

  1. 结构对齐：目录改名、ramdisk 布局从 sbin 时代改成 system-as-root 时代；
  2. 解密方案换代：手动管理 keymaster 3.0 服务 → VINTF manifest + keymaster 4.0 自动注册，fstab 从 FDE 改 FBE；
  3. OrangeFox 化：公共树 import、OF_* 系列适配 flag。

照着本文逐节对照，任何一台 A9 时代的 TWRP 设备树都可以用同样的思路搬进 OrangeFox A12.1。
